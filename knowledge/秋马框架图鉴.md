## 二、四轮全量排查记录

这部分是**方法记录**，不是框架内容。留着是因为：同样的方法可以复用到别的课程资料上（已固化为 [`tools/find_framework_images.py`](../tools/find_framework_images.py)），而且里面有一次判断失误值得记住。

### 第一轮：人工翻看

只转录了 4 张（四阶模型、大抄、双三角、双三角武器库）。

### 第二轮：特征扫描 + 人工复核前 50

- **扫描方法**：对 1063 张图计算边缘密度、颜色数、亮底占比、画幅，用 4 张已知框架图作标尺（命中 4/4），筛出 **181 张**候选，人工复核**前 50 名**
- **成果**：新增 8 套框架 + 3 份实物范本
- **当时的已知缺口**：候选中第 51-181 名未逐张复核；被筛掉的 882 张未看

### 第三轮：全量扫完（亮底剩余 123 张 + 深底 104 张）

补完第二轮未复核的亮底候选，并**放宽阈值新增一轮深底扫描**（`light<0.55`，专门找被亮底阈值误杀的深背景框架图）。

**深底扫描结论：没有框架被误杀。** 104 张深底候选**全部不是框架图**，构成如下：案例贡献者人物卡（`YITANG MARATHON LIVE 2026 AUTUMN` 系列，每位案主一张）、马拉松奖牌与奖状、课程视频截图、金句字卡、品牌海报。

**这个结论本身有价值**：说明这套课件的框架图**一律采用浅底设计**，亮底阈值没有造成系统性遗漏。

亮底剩余部分又找到 **4 套框架 + 8 份实物范本**（F13-F16、以及 S02-S05 里的大部分实物）。

| 项 | 数 |
| --- | --- |
| 配图总数 | 1063 |
| 亮底候选（`edge≥0.07, light≥0.55, area≥0.9MP`） | 181（去重后） |
| 深底候选（`light<0.55, edge≥0.075, ncol≤9000`） | 104（去重后） |
| **人工复核** | **285 张全部** |

### 第四轮：补扫「低边缘密度」缺口

**第三轮结束时我判断「剩下 775 张没必要看」，这个判断是错的。**

拆解落选原因后发现，775 张里有一类落选理由可疑：**269 张「边缘密度 < 0.07」**。真正担心的漏网场景恰恰就是它 —— **「大字 + 箭头」的简洁概念图**，线条少、留白多，边缘密度天然就低。

于是做了一次二阶筛选：在这 269 张里取「颜色数 ≤ 800（扁平设计）且亮底 ≥ 50%」的，**得到 78 张**，全部复核。**结果确实漏了两套框架。**

| 类别 | 数量 | 说明 |
| --- | --- | --- |
| 复核的缺口图 | 78 | 大画幅 + 扁平设计色 + 亮底 + 低边缘密度 |
| **新增框架** | **2** | [Y 模型画布](秋马卡片/框架/F17-Y模型无限进步画布.md)、[知识库处理流程六帧](秋马卡片/框架/F18-知识库信息处理流程.md) |
| 新增实物范本 | 1 | `yj-business-analysis` Skill 定义 |
| 「敲黑板，说重点」章节标题卡 | ~68 | 不是框架，但**能还原讲解的分段结构**，个别卡片（如 `P1/183`）补上了逐字稿抓取截断的信息 |
| 小程序/UI 截图 | ~7 | 温校长造梦空间合伙人系统 |

## 三、最终账与剩余风险

| 项 | 数 |
| --- | --- |
| 配图总数 | 1063 |
| 人工复核 | 363 张（285 + 78） |
| **框架卡** | **19 张**（覆盖 20 套框架，MBA 爬山与管理地图合并为一张） |
| **范本卡** | **5 张**（覆盖 12 份实物范本） |

> **口径说明**（避免自己加算对不上）：上面四轮逐轮累计是 **4 + 8 + 4 + 2 = 18 套 AI 框架**。
> 另有 **2 套非 AI 方法论**（MBA 一路爬山体系、一堂管理地图）在第三轮以「顺带记录」出现，未计入那一轮的 4 套。
> **18 + 2 = 20 套**，由 **19 张卡**承载 —— 那 2 套非 AI 的合并在 [F19](秋马卡片/框架/F19-MBA爬山体系与管理地图.md) 一张卡里。
> 范本侧：3 + 8 + 1 = **12 份**，由 **5 张范本卡**承载。

**剩余真正未看的**：361 张小图（<0.9MP，多为表情、图标、小截图）、138 张深底多色照片、约 191 张低边缘密度但颜色多或深底的（照片、渐变背景）。

这三类的框架概率已经很低，**但不再声称「没必要」—— 上一次这么说就翻车了**。

**其他已知风险**：

- 全部转录为人工读图，可能有识别误差，**尤其是小字号的表格单元格**。已在各卡片里逐条标注疑似 OCR 噪声的位置
- 半肥猫与王木匠两份文档的配图（共 220 张）也在扫描范围内，未发现框架级图片 —— 半肥猫的方法论本来就写在正文里

## 四、这件事的普遍教训

> **这套逐字稿的抓取方式保住了图片文件，却没有保住图片里的信息。**

任何只读 `.md` 的 Agent 都会错过核心框架。归档任何「正文 + 大量配图」的资料时，都必须单独跑一轮配图排查 —— 已固化进 [`skills/course-archive-workflow/`](../skills/course-archive-workflow/SKILL.md)。
