# 方法论与框架

> 📌 秋马的四阶飞轮与双三角有**更完整的图版**（含每阶段避坑清单、策略库、六项能力的四级修炼路线），已从课程配图转录至 [秋马框架图鉴.md](秋马框架图鉴.md)。本文是文字侧的梳理，两者互补。

## 一、AI 十倍速飞轮（本次马拉松主框架）

四个周期，**每个阶段的主要矛盾和驱动力都不一样**：

| 阶段 | 从什么到什么 | 驱动力 | 对应赛段 |
| --- | --- | --- | --- |
| 启动期 | 从上手恐惧到真爽一次 | 信心飞轮 | 新人启动期 |
| 加速期 | 从简单能做到持续变强 | 结果飞轮 | 螺旋加速期 |
| 复利期 | 从一个人做到团队体系 | 复利飞轮 | 复利打造期 |
| 迁移期 | 从单一领域到跨界领先 | 跨界飞轮 | 跨界迁移期 |

原图还标了每阶段的**时间单位**（启动期以天、加速期以周、复利期以月、迁移期以年为单位）和三个构成要素，以及每阶段的三条避坑与完整策略库——见 [秋马框架图鉴.md](秋马框架图鉴.md)。

**最实用的一条**：卡住或带不动下属，往往是**阶段与飞轮错配**——
- 新人阶段过早考虑封装复制 → 太难无法实施
- 老人阶段还在做信心建立 → 早就过了，只有高难的封装和跨界才有进步空间

各阶段的核心心法：
- **启动期**：争取爽一次。主动降低难度——缩小场景、缩小项目，感受工具的爽、积累的爽、凑齐的爽
- **加速期**：对自己持续不满意。核心不是「让 AI 多干活」，而是进入「人和 AI 互相教」的增强循环——教 AI 的爽 + 被 AI 教的爽 + 双向加强的爽
- **复利期**：把个人能力固定封装成长期稳定的系统
- **迁移期**：能力是可以迁移的。从经验到方法，从方法到底层框架，从底层框架到跨行业适配

## 二、双三角

一堂的人机分工范式，3+3 个核心要素，用控制变量的思维方法提炼。

✅ **已从原图确认**（P1 `images/093.jpg`、`094.png`）：**人类三角 = 审美、体系、创造力；AI 三角 = 场景、基本功、数据**。完整子项与六项能力的四级修炼路线见 [秋马框架图鉴.md](秋马框架图鉴.md)。

核心主张只有两行：
> AI 不是一个单点问题，而是一个系统工程；
> 而双三角给了我们一套基本的科学因果框架。

**它解决什么**：
1. 消除「单点迷信」——不再迷信工具、迷信 AI、迷信人、迷信经验
2. 结果不好时，不怪 AI 也不怪人，而是**双三角不够强**，那就去把它拉满

**四种使用姿势**（砻沣的成长路径就是这四步）：参与双三角 → 管理双三角 → 补齐双三角 → 创新/细化双三角

**关键提醒**：课程明确承认此前**把双三角讲成了静态模型**——「只要审美够强、体系够强就很行」，但把卷子做对本身就是一个漫长的学习和试错过程。这次修正为**动态螺旋**：
- 人强了 → 如何赶紧让 AI 学会，变成 AI 工作的一部分？
- AI 强了 → 如何倒逼人类提升，持续抬高工作的天花板？

## 三、半肥猫的知识管理五阶段

详见 [半肥猫-YAML知识卡片法.md](半肥猫-YAML知识卡片法.md)。骨架：

| 阶段 | 遇到的问题 | 做了什么 |
| --- | --- | --- |
| 一、把知识带进对话 | AI 手里没有我的东西 | 三类内容（提示词/专业知识/成功案例）+ 三个动作（转格式、去噪、分类保存） |
| 二、研究 RAG | 资料越多效果反而越差 | 原子化 + 结构化头部 + 打标签分库 |
| 三、封装 Workflow | 知识进了 AI，但没进团队；自己成了「人肉接口」 | Workflow 六要素；把隐性知识显性化、审美资产化 |
| 四、追求稳定灵活 | Workflow 不灵活、维护成本高 | Skill / Agent / 数字员工 / MCP |
| 五、跨 AI 工具协同 | 多工具多项目无法交接 | 项目知识库五件套 |

**Workflow 六要素**：知识库（业务事实、案例、边界）、Prompt 与规则（怎么处理）、检索方式（去哪找什么）、明确任务（把「帮我做内容」变成可执行动作）、输入输出标准、验收方法。「这六件事绑在一起，才比较像一条生产线」

**Skill 与 Agent 的区分**：
- Skill 解决**一个能力怎么被封装**。不应只有提示词——还可包括查询代码、知识库匹配、强制检索、前端判断、路由、后端处理、边界约束、输出格式，以及测试和验收
- Agent 解决**一类任务应该怎么调度这些能力**。「如果 Skill 是技能，Agent 就像一个拥有多项技能的员工」
- **数字员工 = 不同的知识消费入口**。不是起几个名字，也不是越多越厉害。它们共享企业知识库，但每个岗位必须有自己的工作边界、输入、输出和验收标准

**多 Agent 必需的三套机制**（否则「只是把很多窗口堆在一起，把混乱也一起放大」）：协同机制与共享记忆、交接时说清做到什么程度怎么评估、文件的读写权限边界

**项目知识库五件套**：
1. **总控文档**——项目说明书：解决什么问题、文件怎么命名、谁负责什么、能做什么不能做什么、哪个 AI 负责 PRD/拆任务/施工/测试、任务清单和收件箱在哪
2. **需求说明**——目标、范围、输入、输出、优先级
3. **任务清单**——拆成可执行、可勾掉的任务
4. **收件箱**——做完不是发一句「我完成了」，而是把施工文件、说明、注意事项放进去，让下一环节有东西可接
5. **结果归档区**——验收过的结果、做过的判断、遇到的问题和解决方式

流程：**需求进入项目库 → AI 读取任务 → 分工执行 → 结果写回 → 清理任务 → 下一轮调用**

> 换模型也一样，它接的不是上一段聊天记录，而是这个项目已经沉淀下来的状态。

## 四、防幻觉 / 质量保障

### 郁金星的三层交叉验证
1. **多 AI 交叉**——重要内容至少经过 3 个模型，先把互相存疑、冲突之处找出来
2. **人工 + AI 交叉**——权威资料、行业报告、专家访谈逐项对照时间线、基准数据、案例事实
3. **把自己的资料和规则交给 AI**——并明确规定：哪些数据必须和原始资料对得上，对不上的**以人工资料为准**

### 劉衛的知识链接四类
**逻辑链、因果链、反例链、案例链**。新知识进入时全库搜索建立关联，产出时可沿链接追溯来源。
> 这种做法不能消除幻觉，但能提高追溯和发现错误的概率。

### 劉衛的三库交叉
想捞事实去**「实事求是」**，想捞想法和可能性去**「解放思想」**，想捞自己验证过的去**「知行合一」**。三类交叉得结论，若相对一致则可信度大增。（大库跑一轮校验工作量庞大，他是**分段校验**而非一次跑完）

### 半肥猫的质量复利公式
三步任务，每步 0.75 → 整体 **0.421**；每步 0.95 → 整体 **0.857**。
> 同样是三步，每个环节更努力打磨一些，最后交出去的结果，就会有很大的不同。

### 天末的两道闸
长程任务设 **12 小时上限**防止越跑越偏；关键判断做**红蓝军对抗分析**，从不同立场再看一遍。

### 半肥猫的人工介入三节点
不是全程盯，而是重度参与三处：
1. **项目开始**——反复问 AI：你理解的目标是什么？做了哪些假设？哪些不在范围里？有没有反例？
2. **AI 说完成时**——你怎么证明完成了？有没有异常？这个异常是表面问题还是根因问题？
3. **结果交付前**——人做最终验收。方向对不对、商业风险要不要承担，必须人来判断

## 五、砻沣的 Partner 制作流程
1. **找准场景**：先围绕 TCPR 充分做加法，再做 ROI、能力层级和内核边界的减法
2. **充分准备**：用双三角想清楚审美、体系和数据
3. **MVP 验证**：分案例、分版本，让有判断力的人测试并形成共识
4. **工程化实现**：处理边界条件、约束、Bug 和交互体验，直到足够稳定再发布

配套的数据包四要素：核心定义要对齐、执行框架要具体、判断标准要清楚、事例样本有帮助。

## 六、杨晓光的陌生领域七动作
定目标（先确认最终任务目标和产出）→ 补认知（围绕任务补必要常识）→ 看教材（找该领域最核心教材自己啃）→ 学论文（看前沿在研究什么）→ AI 拆解（把看不懂的概念拆成问题）→ 专家确认（确认没走偏）→ 假设验证。**其中 2-7 循环**。

> 进入陌生领域，不要想着先把行业全学完，而是围绕真实任务快速学习，补到够用即可，再用一个个结果验证自己是否真的初步入门。

他的四种元能力：定义问题、组织知识、设计人机边界、项目沉淀为产品。

## 七、花辣子米的工业解题六动作
找准真实问题明确成功标准 → 结合业务事实和理论经验形成初步认识 → 提出大胆假设用小实验快速验证 → 把理解做成能运行能检验的模型 → 从可控实验走向真实现场 → 用现实反馈持续更新模型和判断。

课程点评：这既是双三角，也是 **Y 模型**——往下找规律，把理论和事实放在一起，再通过假设、建模和实验，用真实反馈一次次修正判断。

## 八、贺雷的组织落地四步
1. **先搞定真正的一号位**（不一定是你自己）：零门槛 + 先打痛点制造 AHA 时刻
2. **再推高管层**：培训（演示真实成果，不讲理论）+ 给任务（限期交自己业务痛点的原型）+ 定原则（业务 owner 就是智能化 owner，没有信息部）
3. **选高杠杆场景开刀**（不选小而安全的试点）：所有关键人都参加、表现公开、复利显著
4. **用「赛跑」点燃团队**：「你们做一套，我做一套」——既制造压力又给自己兜底

**AI+ 与 AI 原生的分界线**（Truman 的判词）：用 AI 做纪要、列待办、会前查资料，那是在**旧流程上打补丁**；把整个数据和决策循环从头推演一遍，一开始就按 AI 能读、能处理、能调用的方式设计数据、标准和流程，让 **AI 进入主循环**，才叫 AI 原生。

## 九、半肥猫的范式复利（四个动作）
**拆分问题 → 设定标准 → 小步验证 → 沉淀可复用结构**

他强调这套方式不是 AI 来了才有的——没有电脑时学 Photoshop，是先啃说明书、把菜单手工画出来；后来做网页做 SEO 也是先拆结构再组合测试。**AI 只是把这套做事方式放大了**。

配套的四个关键词：**协作桥梁、问题驱动、范式复利、拒绝焦虑**。

关于「拒绝焦虑」，他的完整表述值得原样引用：
> 不是拒绝学习，也不是拿「我不是技术人员」给自己找借口；而是拒绝被每一个新名词牵着跑。该学的还要学，新工具也可以试，但要从自己的位置出发，围绕真实问题去学。

> 技术是公器，经验是私产。公器会越来越便宜，越来越容易被大家使用；但你在一个行业里真正做过的事情、踩过的坑、形成的判断，反而会越来越值钱。

## 十、十指模型（王木匠那份，非 AI 主题）
一堂「讲香基本功」的表达武器库，十种手法：**场景化、口语化、数字化、故事化、素材化、比喻化、金句化、情绪化、冲突化、升华化**。

王木匠的延伸做法：读《文案的基本修养》后，把十种策略与**审美价值、娱乐价值、情感价值、知识价值、使用价值、社交价值**做交叉对应表，用来回答「我面向什么人群、目标是什么、侧重点应该是什么」。
